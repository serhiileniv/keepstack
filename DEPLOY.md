# Deploy

Two surfaces, both free, from one repo.

## GitHub — the repo

The repo *is* the product for this audience: stars, issues, `git clone`. `README.md` is
generated by `build.py` and renders as the hub itself on the repo front page.

```bash
cp -r hub ../ai-hub && cd ../ai-hub
git init && git add . && git commit -m "Initial hub"
gh repo create ai-hub --public --source=. --push
```

Enable **Issues**. That's the whole feedback mechanism, and per `PLAN.md` milestone 4, a
stranger opening one is a real signal.

## Cloudflare Pages — the site

`site/index.html` is **committed**, so Pages needs no build step and there is nothing that can
break when a build image changes.

1. Cloudflare dashboard → Workers & Pages → Create → Pages → Connect to Git.
2. Pick the repo. **Build command:** *(leave empty)*. **Output directory:** `site`.
3. Deploy. You get `<project>.pages.dev` immediately.

Every push rebuilds. No account, no database, no functions — per D6, nothing here costs money
per visitor.

### Domain — later

Don't buy one until `PLAN.md` milestone 2 is done. When you do: register **at Cloudflare**, at
cost (~$12/yr, no second-year markup), then Pages → Custom domains. HTTPS is automatic.

## The loop

```bash
python3 build.py --stale     # what's overdue — start a burst here
# ...re-check, edit entries/, bump last_checked + checked_against
python3 build.py --check     # validate before committing
python3 build.py             # regenerate README.md + site/index.html
git commit -am "Re-check pass" && git push
```

`--check` is the gate worth respecting: it fails an entry with an empty `checked_against`, or a
`dropped` verdict with a thin explanation. Both are the failure modes that would make this just
another undated list.
