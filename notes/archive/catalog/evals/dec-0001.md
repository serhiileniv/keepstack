# Eval — Putting client code through AI tooling

A decision eval tests the **expiry trigger**, not the advice. This one makes a *factual claim
about vendor terms*, which means it is the artifact most likely to become quietly false.

## How to re-run

1. Open the current business/commercial terms for every tool named in the clause template.
2. Read the sections on **training on submitted content** and **retention**.
3. Check whether a zero-retention or dedicated-tenancy tier now exists that would change what
   the clause should say.
4. Check for new deployer-side obligations under regional AI regulation that require disclosure
   beyond a contract term.

## Inputs

The list of named tooling in the clause, plus the URLs of each vendor's business terms and
retention documentation. **Keep the URLs in this file** — chasing them down is most of the cost
of the re-run.

- [ ] tool 1 — terms URL: _to fill on first run_
- [ ] tool 2 — terms URL: _to fill on first run_

## Pass criteria

- [ ] Every factual claim in the clause template is still true of the current terms, quoted
      verbatim from the vendor page.
- [ ] No new tier or option exists that would materially improve the clause.
- [ ] No new disclosure obligation applies that the clause does not cover.
- [ ] The "when this is wrong" list still covers the regulated cases correctly.

**Any single fail flips this artifact to `stale` immediately.** A contract clause that misstates
vendor terms is worse for the buyer than no clause, so this one does not get a grace period.

## Models to test against

N/A — this is a documentary check, not a model behaviour. Do it by reading, not by asking a
model what the terms say.
